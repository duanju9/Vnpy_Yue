# 研究回测交付方法论（与具体策略解耦）

本技能描述 **如何做「可交付、可复核、可扩展」的回测研究包**，不绑定某一类信号或某一文件夹命名。具体策略代码仅作为实现示例，**以你仓库里真实脚本为准**。

---

## 1. 交付物目标

| 目标 | 说明 |
|------|------|
| **可复核** | 他人能复现：数据快照、参数、版本号、运行命令、产物路径。 |
| **可阅读** | 不看代码也能懂：假设、表格口径、结论边界（样本内/无滑点等）。 |
| **可扩展** | 换策略、换池子、换打分维度时，目录与文档结构不大改。 |

---

## 2. 文件夹规格（推荐模板）

可按项目习惯微调，建议 **一层一个职责**：

```
<研究主题>_<日期或区间>/
├── 说明与结论.md          # 主叙事：数据、假设、结果摘要、局限与下一步
├── 分发说明.md            # zip 含什么/不含什么、阅读顺序、依赖环境
├── 跑批记录_YYYYMMDD.md   # 当次命令、产物文件名、关键数字速查（可多条）
├── 数据/ 或 测试成分股/    # 股票池/因子输入 CSV 等快照（带日期或批次名）
├── 产物/                  # xlsx、图表、生成的 md（与「源码」分离）
├── 源码/                  # 可选：脚本快照 + README 说明「真源在仓库路径」
└── 分析_*.py              # 可选：从产物 xlsx 再生成报告（避免重复拉行情）
```

**命名区分度**：产物文件名带 **项目前缀 + 参数标签 + 时间戳**，避免与全局 `output/` 默认名混用。

## 3. 表格与 Excel 输出规范

### 3.1 分层

| 层级 | 典型内容 | 读者 |
|------|----------|------|
| **汇总（每标的一行）** | K 线区间、成交笔数、展示用本金、手数、费率、核心收益指标、环境对照列、过程风险指标 | 横向对比 |
| **逐笔** | 每笔买卖时间、价格、多口径收益率、费用、净额、平仓原因 | 对账、归因 |
| **截面统计** | 全样本均值/中位数、子集（如仅成交>0） | 一页看全局 |

### 3.2 口径必须在文档中写清

- **价上收益** vs **扣费后收益** vs **金额**：分子分母是否含佣金、是否同一基准（如「扣费后收益率」应对齐「净盈亏」与「买入名义本金」）。
- **区间基准**（若提供）：「全程持有」型指标（如区间首 open → 末 close）与 **策略复利/净值** 不是同一对象，**不可**用心算混除反推「隐含本金」。
- **是否跑赢基准**：逐行比较策略总收益与基准收益时，写明比较符（> / < / 持平容差）及全表 **跑赢/跑输/持平** 家数统计。

### 3.3 代码侧与文档侧一致

新增列时同步：**引擎汇总 dict**、**批量 `summary_col_order`**、**逐笔 `detail_col_order`**、以及 **说明与结论** 中的列释义表。

## 4. 经济假设与「滑点」

在 **说明与结论** 与 **Excel 元数据/meta** 中固定写明（数值与引擎一致）：

| 项 | 说明 |
|------|------|
| **展示用本金** | 仅用于换算权益/报表展示时，与真实资金规模无关。 |
| **每笔股数 / 仓位规则** | 固定手数、等权、或按资金比例；影响「元」与「%」对照。 |
| **佣金** | 单边 bps、是否双边、计费基数（成交额）。 |
| **滑点** | **若回测引擎未实现滑点**，须明确写「假设按挂单价/收盘价成交，无额外冲击」；若后续实现，在 meta 增加 `slippage_bps` 或阶梯表并改文档。 |
| **复利连乘方式** | 多笔之间是否全仓滚入下一笔；与单利/组合层面区别写一句。 |

**原则**：文档声明的假设 ≤ 代码实际能力；缺项不要写「已考虑滑点」。

## 5. 新研究策略的「打分」方法（通用框架）

打分是 **研究标尺**，非投资建议；公式应 **可公开、可复算**。

### 5.1 设计步骤

1. **定义目标**：例如偏收益、偏回撤、偏相对基准、偏胜率稳定性等（可多目标加权）。
2. **选截面**：全体成功回测 vs 仅成交>0；是否剔除 ST、上市不足 N 日等，写清。
3. **维度与满分**：建议 3–5 维、总分 100；每维 `min(满分, max(0, 仿射变换(指标)))` 避免单项爆表。
4. **等级**：如 A/B/C/D 与总分阈值，在 md 与 meta 中一致。
5. **敏感性**：改一个权重后结论是否翻转；在附录记一句。

### 5.2 与「高波动池」叙事分离

若股票池刻意选高波动（如热榜），打分里应区分：

- **环境指标**（池内基准涨跌、波动幅度），与  
- **策略指标**（复利、超额、胜率、回撤）

避免用单一「是否跑赢全程持有」否定波段类规则；可在打分中单独一维「相对基准」并设下限/软惩罚。

### 5.3 产物

- 评分逻辑写在 **脚本注释 + 生成 md 表格** 两处，避免口径漂移。
- JSONL / meta 可存分项与总分，便于多跑次对比。

---

## 6. 文档模板要点

- **说明与结论.md**：数据范围、参数表、主要数字、**局限**（样本内、无冲击成本、无停牌模型等）、改进方向。
- **分发说明.md**：依赖（Python 版本、数据源、是否需终端）、**不包含**什么、建议 zip 命名。
- **跑批记录**：一次运行一份或一节，只记「文件名 + 数字」，少议论。

---

## 7. 新策略接入检查清单

- [ ] 参数进入 argparse / Namespace，并在 meta 落盘。
- [ ] 汇总与逐笔列名中英或全中文统一，且 `reindex` 列顺序完整。
- [ ] `capital` / `lot` / `commission_bps` /（若有）`slippage` 在摘要与说明中一致。
- [ ] 若有基准列，提供 **策略减基准** 与 **是否跑赢** 或等价信息。
- [ ] 交付包内若有「源码快照」，**README** 写明真源路径与「勿在快照内改 `_REPO` 期望」类提示；一键跑批用 **仓库根目录 + subprocess 调正式脚本** 或等价方式。
- [ ] 大文件与密钥：`.gitignore` 策略、不把 API key 打进 zip。

---

## 8. 与具体实现的关系

本技能 **不替代** 仓库内某支脚本的 docstring；实现以 **`examples/quick_tests/`**（或你项目实际路径）下代码为准。新增策略时，将本节作为 **检查表**，把最终口径写回该策略的 `说明与结论.md` 即可。
